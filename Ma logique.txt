# Ma logique

## Comprehension

Le but premier du projet est de ranger des nombres donnés par ordre croissant.
Dans le projet on a deux pile(a et b). a stocke tout les chiffres donnés en parametre.

Avec la pile a, on le remplit des chiffres donnés et la pile b qui est vide(nous sert a trier)

A la fin, les chiffres doivent être dans l'ordre croissant, et la pile b doit etre vide.

En gros on doit ranger la pile a dans l'ordre croissant des chiffres tout ça avec les 11 opérations qu'on nous donne.

*Le but finale du projet est de ranger avec la plus courte combinaison possible d'opérations.*

Pour réaliser le moins d'opérations possible, on nous a donné 4 strategy : simple, medium, complex et adaptatif.

Avant de commencer a ranger ou utiliser une strategy, il faut calculer le desordre.

le desordre c'est le truc qui permet de savoir combien d'inversion on va faire, en gros il montre comment la pile est derangé.

On doit avoir calculer le desordre avant tout mouvement.

Du coup en fonction du desordre et si on nous donne pas la strategy(du coup c'est adptatif), on doit choisir les strategy / comment ranger.

il faut avoir un bench, qui est le resumer de tout ce qui c'est passé.

le bench s'affiche sur la sortie d'erreur(2)

il faut afficher les erreurs sur la sortie d'erreur (2) si le nombre donné n'est pas un entier, s'il y'a des doublons ou le nombre depasse les limites du INT.


On doit pouvoir dire pour chaque operation combien de fois elle a été utilisé, on doit pouvoir afficher le nom de l'operation quand on l'utilise.
On doit pouvoir aussi dire combien d'operation au total (en utilisant les 11 op mon code) a été réalisé pour ranger la pile.

on doit pouvoir afficher la liste des opérations (pb, ra, rra...), une par ligne sur la sortie standard.


Pour que le projet soit carré il faut pouvoir :

- reconnaitre les options et les arguments a ranger
- selectionner une methode de calcul en utilisant "--simple, --medium, --complex"
- voir le bench(
	, qui affiche le desorde en pourcentage avec 2 chiffre apres la virgule
	, le nom de la statégie et la complexité de la strategie
	, qui affiche le nom de l'op et le nombre de fois qu'elle est utilisée (en gros le compte de chaque op)
	, le nombre total d'operation effectué)
	pour activer le bench on utilise (--bench)
- coordonner les operations dans les strategy

## Réalisation

j'ai diviser le projet entre 6 fichiers : algos, analysis(analyse), bench, ops(operations), parsing et stack.

Vu qu'on aura beaucoup de variables et de contexte a utiliser, je pense qu'il faut definir plusieurs structure :

- une structure qui englobe tout ce dont on a besoin dans ce projet (il doit contenir les piles a et b, les compteurs
	, les options(strategy utilisé, la complexité de la strategie, le compte pour chaque operation, le nom de chaque operation, le total de toute les operations faites, le desordre, et si on affiche lbench ou pas))

- une structure correct de pile(pile a et b ont la meme structure)

- enumerer les strategies et les ops, ça sera plus facile l'utilisation et tout.

/* ************************************* Les structures mis en place ****************************************** *\

/* ***************** les structure enumerés des strategie et des operation *********************** *\

typedef enum e_op { SA, SB, SS, PA, PB, RA, RB, RR, RRA, RRB, RRR }	t_op;

typedef enum e_strat { ADAPTIVE, SIMPLE, MEDIUM, COMPLEX }	t_strat;

dans t_op, on a toutes les opérations listées, pareil pour les stratégies dans t_strat.

/* ***************** Structure de pile *********************** *\

typedef struct s_node
{
	int				value;
	int				index;
	struct s_node	*next;
}	t_node;

value = la valeur a l'interieur de ce maillon.
l'index = nous permet de savoir il doit etre a quelle place normalement quand c'est trié
next = un pointeur sur le prochain maillon.

/* ***************** Structure du projet *********************** *\

typedef struct s_ctx
{
	t_node		*a;
	t_node		*b;
	int			count[11];
	int			total;
	int			bench;
	t_strat		strat;
	double		disorder;
	const char	*name;
	const char	*cplx;
	const char	*op_names[11];
}	t_ctx;

a = pile a
b = pile b
count[11] = un tableau representant les 11 operations ou les elements du tableau recense combien de fois chaque operation a ete utilisé (par exemple, prenons SA est representé par 0 si count[0] =  10, ça veut dire SA a ete utilisé 10 fois)
total = le nombre total d'operations
bench = si on affiche le bench ou pas, il prend 0 ou 1(faux ou vrai afin de savoir si on affiche ou pas).
strat = la strat utilisé
disorder = le desordre initial dans les nombres mis dans la pile a(reste en double, on le mettra en pourcentage quand on affiche le bench)
name = le nom de la srtategie utilisé
cplx = la complexité de la strategie (O(n²), etc...)
op_names = un tableau representant les 11 operations ou les elements du tableau represente le nom des 11 operations.

### ANALYSIS

Dans ce dossier on trouvera la fonction pour calculer le desordre et pour pouvoir faire la normalisation.

La normalisation c'est le fait de remplir index de la structure de la pile(pas du projet) de la position normale qu'elle doit avoir quand elle est triée


*La fonction pour calculer le desordre*

/* ***************** analysis/disorder.c *********************** *\

double	compute_disorder(t_node *a)
=>
	i : Parcourt la pile et représente le premier élément de la comparaison.
	j : Parcourt les éléments qui suivent i.
	mistakes : Compte le nombre d'inversions trouvées.
	pairs : Compte le nombre total de comparaisons effectuées.


*La fonction pour faire la normalisation*

/* ***************** analysis/normalize.c *********************** *\

void	normalize(t_node *a)
=>
	i : Parcourt chaque maillon dont on veut calculer l'index.
	j : Parcourt toute la pile pour comparer les valeurs avec celle de i.
Presque meme logique que la fonction du desordre, juste au lieu de compter les inversions qu'on peut faire, on calcule les index.
